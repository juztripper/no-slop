# NO SLOP 0.2.0 — direct OpenRouter preview

**Developer preview.** Download the extension ZIP and checksum from the [0.2.0 release](https://github.com/juztripper/no-slop/releases/tag/v0.2.0).

Use NO SLOP with your own OpenRouter key directly in the extension. A separate detector server, Node.js and a running terminal are no longer required for the default setup. Provider usage is billed to your account; no project-funded key or credits are included.

## Install

1. Extract `no-slop-0.2.0-chromium.zip` into a permanent folder.
2. In Chrome or Edge, open the extensions page, enable Developer mode and load the extracted folder as an unpacked extension.
3. Open NO SLOP settings → **Privacy & connection**, choose **OpenRouter** and save your own key from [OpenRouter](https://openrouter.ai/settings/keys). Set a provider dollar spending limit on that key.
4. Test authentication, choose a daily request cap, review the data-sharing notice, consent and enable analysis. Refresh existing feed tabs.

The connection test makes no paid model request. Real filtering does. The default local allowance is 100 paid requests per UTC day, configurable from 1 to 10,000; failures can count. This is not a dollar spending limit. Set the independent limit in OpenRouter.

## What changed

- New installations use direct OpenRouter processing, with explicit consent before analysis.
- Keys stay in device-local storage restricted to trusted extension contexts, never Chrome Sync, content scripts or page scripts. This is not an encrypted credential vault.
- The background worker handles bounded text requests, typed-response validation, shared verdict policy, persistent daily request reservations and a bounded hash/verdict cache without persisted raw text.
- Direct processing uses visible text, titles, captions, snippets and context. It does not fetch destination pages or images.
- Optional self-hosted mode remains available, including guarded public destination inspection and a separate service token.

## Upgrading from 0.1.0

Replace the files in the same extension folder, reload it and refresh feed tabs. Existing settings retain self-hosted mode. Switching to direct processing requires saving your own OpenRouter key and consenting again. The extension does not silently migrate page data to a different processing mode. The old server can be stopped after you switch.

The source-development workflow still needs Node.js 24+ and npm. The interface preview and deterministic tests need no provider key. ## Known limits

This remains an unpacked developer preview, not a browser-store release. Passing deterministic tests is not live qualification of a user's provider account or authenticated social feeds. Unknown layouts, uncertain judgments and provider failures leave content visible. Images and audio/video are not analyzed. The authored evaluation results are historical development evidence, not a representative accuracy benchmark.

The ZIP contains the extension, licenses, installation/privacy notes and these release notes. `SHA256SUMS` records its checksum. No key, server process or provider account is bundled.
